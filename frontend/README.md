# Frontend (Vue 3 / Vite)

UI для онлайн-чата:
- можно создать комнату с обязательной темой;
- можно подключиться к любой свободной комнате;
- нельзя подключиться к собственной комнате из списка свободных (если совпадает `user_id`);
- после входа открывается WebSocket-чат комнаты;
- при отключении автора фронтенд получает `room_close_scheduled`, а затем `room_closed` по таймауту.
- при обновлении страницы фронтенд пытается восстановить последнюю активную комнату.
- для подключения к комнате нужно заполнить поле `Ваше имя`.
- в чате показываются системные сообщения о входе и выходе участников.
- в композере есть быстрые кнопки смайликов; смайлики отправляются как обычные сообщения.
- текст сообщения поддерживает безопасное форматирование (`**жирный**`, `*курсив*`, `` `код` ``, `~~зачеркнутый~~`, переносы строк).
- применена единая визуальная система: контрастный editorial-стиль, двухпанельное лобби (панель управления + board свободных комнат), рабочее окно чата, цветовые роли сообщений (you/peer/system) и адаптивная мобильная верстка.
- в режиме комнаты блок сообщений не растягивает layout и прокручивается внутри `messages-panel`; при новых сообщениях выполняется автопрокрутка вниз.
- список свободных комнат обновляется автоматически через `WS /ws/lobby` без ручного refresh.
- в шапке активной комнаты выводится полный `room_id` (UUID), чтобы его можно было скопировать и передать собеседнику.
- при обрыве соединения гостя (закрытии вкладки/окна) автор сразу видит системное сообщение о дисконнекте, даже до истечения grace-таймаута.

## Требования
- Node.js 20+
- npm 10+

## Конфигурация
- `VITE_API_BASE_URL` — HTTP API backend (по умолчанию `http://localhost:8000`).
- `VITE_WS_BASE_URL` — WebSocket base URL (опционально; если не задан, вычисляется из `VITE_API_BASE_URL`).
- `VITE_WS_PROTOCOL_MODE` — режим протокола websocket:
  - `auto` (по умолчанию): `https -> wss`, `http -> ws`;
  - `wss`: всегда использовать `wss://`;
  - `ws`: всегда использовать `ws://` (отключить `wss`).
- Если `VITE_API_BASE_URL` не задан и страница открыта по IP/домену, frontend использует текущий хост страницы и порт `8000`.
- `user_id` хранится в `localStorage` (вкладки одного браузерного профиля используют общий идентификатор).
- идентификатор активной комнаты хранится в `localStorage` для восстановления после refresh.
- frontend подписывается на `ws/lobby` и при событиях `rooms_catalog_updated` автоматически подтягивает `GET /rooms/free`.
- `room_id`, который вводится в поле `ID комнаты`, имеет формат `UUID4` и выдается backend.
- интерфейс полностью русифицирован: лобби, чат, статусы, ошибки и системные сообщения.
- если backend применяет geoIP-ограничения, для запрещенной страны операции создания/подключения к комнате отклоняются с явным сообщением backend.

## Установка

```bash
cd frontend
npm install
```

## Запуск в dev

```bash
npm run dev
```

## Проверки

```bash
npm run lint
npm run test
npm run build
```

## Docker

Сборка и запуск только frontend-контейнера:

```bash
docker build -f frontend/Dockerfile -t chat-frontend .
docker run --rm -p 5173:80 chat-frontend
```

Рекомендуемый запуск всего проекта через compose:

```bash
docker compose up --build -d
```

Примеры переключения режима websocket в Docker:

```bash
VITE_WS_PROTOCOL_MODE=wss docker compose up --build -d
VITE_WS_PROTOCOL_MODE=ws docker compose up --build -d
```
