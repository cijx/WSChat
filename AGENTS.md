# AGENTS.md

## Контекст проекта
- Продукт: веб-приложение онлайн-чата.
- Стек:
  - Backend: Python.
  - Frontend: Vue.
- Цель агента: вносить изменения, готовые к релизу, без деградации качества.

## Обязательный стандарт работы
1. Понять задачу и границы изменений (что затронуто в backend/frontend, API, данные).
2. Сделать минимально необходимое и безопасное изменение.
3. Обязательно добавить или обновить тесты под изменение.
4. Прогнать локальные проверки перед сдачей.
5. Сделать саморевью и проверить риски регрессий.
6. В отчете явно указать, что изменено и чем подтверждена корректность.

## Перезапуск проекта после изменений (обязательно)
- После любых изменений в коде или конфигурации запуска агент обязан перезапустить проект.
- Для docker-сценария по умолчанию использовать:
  - `docker compose up --build -d --force-recreate`
- После перезапуска агент обязан проверить доступность сервисов (минимум `docker compose ps` и `GET /health` backend).
- Если перезапуск или проверка недоступны, агент обязан явно указать причину в финальном отчете.

## Тесты обязательны
- Любая новая функциональность должна сопровождаться тестами.
- Любой багфикс должен включать регрессионный тест.
- Для backend обязательны тесты бизнес-логики и/или API.
- Для frontend обязательны тесты компонентов и/или пользовательских сценариев при изменении UI-поведения.
- Нельзя считать задачу завершенной без прохождения релевантных тестов.

## Обязательная самопроверка перед ответом
- Backend: форматирование/линтинг, типизация (если используется), тесты.
- Frontend: линтинг, типизация (если используется), тесты, сборка.
- Проверить:
  - обработку ошибок и крайние случаи;
  - совместимость контрактов frontend/backend;
  - отсутствие очевидных проблем безопасности;
  - что изменения не ломают существующие сценарии.

## Правила сдачи результата
- В финальном ответе агент обязан указать:
  - какие файлы изменены;
  - какие команды проверок и тестов запускались;
  - результаты проверок (успех/ошибка).
- Если что-то не удалось запустить, агент обязан явно указать причину и что именно нужно сделать дальше.
- Нельзя писать "готово", если проверки не пройдены или не были запущены без объяснения причины.

## Актуализация README.md (обязательно)
- Агент обязан поддерживать в актуальном состоянии файл `README.md` в корне проекта.
- `README.md` должен описывать весь проект целиком:
  - назначение продукта;
  - используемый стек и архитектурное деление;
  - структуру репозитория;
  - шаги локального запуска backend/frontend;
  - команды тестов и проверок;
  - важные ограничения/допущения для разработки.
- Любые изменения, влияющие на запуск, архитектуру, зависимости или процессы разработки, должны сопровождаться обновлением `README.md`.

## Ведение memory.md (обязательно)
- Перед началом любой новой задачи агент обязан прочитать актуальные записи в `memory.md`, чтобы восстановить контекст предыдущих целей, решений и результатов.
- Агент обязан вести файл `memory.md` в корне проекта и обновлять его по итогам каждой завершенной задачи.
- Для каждой задачи в `memory.md` фиксировать:
  - цель задачи;
  - что именно было сделано;
  - какие средства/инструменты использовались (команды, тесты, проверки);
  - какой результат получен (включая статус проверок и тестов).
- Запись должна быть краткой, конкретной и проверяемой.

## Приоритеты качества
- Сначала корректность и надежность, потом скорость реализации.
- Предпочитать простые, проверяемые решения без скрытой магии.
- Избегать неявных breaking changes; если они есть, явно отметить.
